# runtime-observability Specification

## Purpose

保障应用运行期故障可被观测：带异常的错误日志以正确级别完整输出、线程与协程的未捕获异常有全局兜底记录、文件日志开关状态跨重启持久保留，使问题发生后始终留有可定位的日志证据。

## Requirements

### Requirement: 带异常的错误日志以 ERROR 级别输出

日志门面的带异常错误接口 SHALL 将日志以 ERROR 级别提交至生效的日志后端，消息文本与异常堆栈一并输出，不因日志级别配置（不低于 DEBUG 的 root 级别）而被过滤。

#### Scenario: 输出错误日志与完整堆栈

- **WHEN** 调用带异常的错误日志接口（如打开文件夹失败、图片解析失败等场景）
- **THEN** 生效日志后端（控制台或文件）输出一条 ERROR 级别条目，包含 tag、消息文本与完整异常堆栈

#### Scenario: root 日志级别为 DEBUG 时依然可见

- **GIVEN** 全局 root logger 级别为 DEBUG
- **WHEN** 调用带异常的错误日志接口
- **THEN** 该条目以 ERROR 级别输出且可见（不得以 TRACE 等低于 root 级别的级别提交）

### Requirement: 线程未捕获异常全局兜底

应用 SHALL 在启动早期注册 JVM 全局未捕获异常处理器，任意线程抛出的未捕获异常以 ERROR 级别记录（含线程名、异常类型与堆栈）后，再按平台默认行为处理；日志系统未完成初始化时 SHALL 通过默认日志实现输出，保证异常信息不丢失。

#### Scenario: 后台线程抛出未捕获异常

- **WHEN** 任意非 UI 后台线程抛出未捕获异常
- **THEN** 日志输出一条 ERROR 级别记录，包含线程名与完整堆栈

#### Scenario: 日志系统初始化完成前发生异常

- **GIVEN** 应用刚启动、日志后端初始化尚未执行
- **WHEN** 任意线程抛出未捕获异常
- **THEN** 异常仍通过默认日志实现（stdout）输出，信息不丢失

### Requirement: 协程未捕获异常兜底

应用 SHALL 为协程作用域提供异常兜底：协程中未被业务捕获的异常以 ERROR 级别记录（含堆栈），不静默丢失。

#### Scenario: 协程内抛出未捕获异常

- **WHEN** 任意应用协程（如 ViewModel 作用域内的异步任务）抛出未被捕获的异常
- **THEN** 日志输出一条 ERROR 级别记录，包含完整堆栈，异常不以无痕方式消失

### Requirement: 文件日志开关持久化

文件日志开关状态 SHALL 持久化到应用配置存储：开关变更时写入，应用启动初始化时恢复；首次启动无历史记录时默认关闭。

#### Scenario: 开启后跨重启保留

- **GIVEN** 用户在设置页将"开启日志存储"置为开启
- **WHEN** 应用退出并重新启动
- **THEN** 开关状态仍为开启，且开启后的日志写入日志文件

#### Scenario: 关闭后跨重启保留

- **GIVEN** 用户在设置页将"开启日志存储"置为关闭
- **WHEN** 应用退出并重新启动
- **THEN** 开关状态仍为关闭，日志不写入文件

#### Scenario: 首次启动默认关闭

- **GIVEN** 配置存储中不存在文件日志开关记录
- **WHEN** 应用启动
- **THEN** 文件日志开关处于默认关闭状态（与既有默认行为一致）
