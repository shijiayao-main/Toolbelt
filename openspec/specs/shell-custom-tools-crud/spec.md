# shell-custom-tools-crud Specification

## Purpose

为 Shell Tools 提供自定义工具的完整增删改能力：覆盖全部四种子节点类型的创建与编辑、自定义分组的增删改与跨组移动、稳定 id 主键与旧数据自动迁移、并发写安全，消除"导入即数据清空"与同名覆盖等数据完整性缺陷。

## Requirements

### Requirement: 自定义工具全类型编辑
自定义工具的创建与编辑 SHALL 支持全部四种子节点类型：普通命令、多选、输入、链式。已有多选/输入工具 SHALL 可原样编辑回填并保存，不发生类型退化或数据丢失。

#### Scenario: 新建多选工具
- **WHEN** 用户在编辑器中选择"多选"类型，填写名称与至少一个选项（名称 + 命令），保存
- **THEN** 列表新增多选工具节点，点击后可选择任一选项独立执行

#### Scenario: 新建输入工具
- **WHEN** 用户在编辑器中选择"输入"类型，填写命令模板（含 `{参数名}` 占位符）与参数定义（名称、描述），保存
- **THEN** 列表新增输入工具节点，执行时弹出参数输入框，参数替换占位符后执行

#### Scenario: 编辑导入的多选工具
- **WHEN** 用户打开由导入创建的多选类型工具进行编辑
- **THEN** 编辑器表单回填原有选项数据，保存后选项数量与内容不丢失、类型不变

#### Scenario: 编辑导入的输入工具
- **WHEN** 用户打开由导入创建的输入类型工具进行编辑
- **THEN** 编辑器表单回填原有命令模板与参数定义，保存后模板与参数不丢失、类型不变

#### Scenario: 导入类型保留
- **WHEN** 用户导入包含多选或输入类型的 JSON 片段后重新加载配置
- **THEN** 工具类型与数据完整保留，不退化为"该类型仅支持展示（导入保留）"之类的占位内容

#### Scenario: 删除自定义工具
- **WHEN** 用户删除一个自定义工具并确认
- **THEN** 该工具从列表与自定义配置文件中移除，其他工具不受影响

### Requirement: 稳定 id 主键与旧数据迁移
自定义工具 SHALL 以持久化的唯一 id 作为主键。工具改名 SHALL NOT 改变其 id；同名工具 SHALL 允许并存。旧版以名称为主键的自定义配置文件在读入时 SHALL 自动迁移为稳定 id 且不丢失任何数据，迁移 SHALL 幂等。

#### Scenario: 改名不重建
- **WHEN** 用户编辑已有自定义工具且仅修改名称
- **THEN** 工具 id 保持不变，不出现同 id 重建、重复条目或历史引用失效

#### Scenario: 同名工具并存
- **WHEN** 用户创建一个与既有自定义工具同名的工具
- **THEN** 两个工具以不同 id 并存，保存后既有工具不被覆盖

#### Scenario: 旧数据自动补 id
- **WHEN** 读入不含 id 的旧版自定义配置文件（名称主键、扁平结构）
- **THEN** 每个工具与分组获得生成的稳定 id，命令、类型、分组归属数据无损

#### Scenario: 迁移幂等
- **WHEN** 已完成 id 迁移的文件再次被读入
- **THEN** 所有 id 保持不变，不重复生成

### Requirement: 自定义分组管理
自定义工具 SHALL 按分组组织。用户 SHALL 能新建分组、重命名分组、删除分组，并在分组间移动工具。删除非空分组时组内工具 SHALL 迁移至默认分组而非删除；默认分组 SHALL NOT 可被删除。

#### Scenario: 新建分组
- **WHEN** 用户新建自定义分组并命名
- **THEN** 分组出现在列表中（位于自定义区域），可在其下添加工具

#### Scenario: 重命名分组
- **WHEN** 用户重命名一个自定义分组
- **THEN** 分组展示名更新，组内工具及其 id、数据不变

#### Scenario: 删除非空分组
- **WHEN** 用户删除一个包含工具的自定义分组并确认
- **THEN** 分组被删除，组内工具迁移至默认自定义分组并保留

#### Scenario: 删除空分组
- **WHEN** 用户删除一个不含工具的分组
- **THEN** 分组被直接删除，无需迁移确认

#### Scenario: 跨组移动工具
- **WHEN** 用户将工具从一个自定义分组移动到另一个分组
- **THEN** 工具 id 与数据不变，仅分组归属变化

#### Scenario: 默认分组保护
- **WHEN** 用户尝试删除默认自定义分组
- **THEN** 操作被拒绝并提示默认分组不可删除

### Requirement: 自定义配置存储结构
自定义配置文件 SHALL 采用分组树形结构存储，子节点 body 类型鉴别 SHALL 遵循主配置相同的整型 type 约定（0=普通、1=多选、2=输入、3=链式），序列化 SHALL 保留完整类型数据。旧版扁平结构（无分组的子节点列表）SHALL 可读入并迁移。

#### Scenario: 旧扁平结构兼容
- **WHEN** 读入旧版无分组结构的自定义配置文件
- **THEN** 全部工具迁移至默认分组，类型与数据无损

#### Scenario: 类型完整持久化
- **WHEN** 保存一个多选或输入类型的自定义工具后重新加载
- **THEN** 从文件读出的 body 类型与字段与保存时一致

#### Scenario: 写入原子性
- **WHEN** 自定义配置写入过程中发生异常
- **THEN** 已有配置文件保持完整可用，不出现半写损坏状态

### Requirement: 并发写安全
自定义配置的读-改-写操作 SHALL 串行化执行：并发保存 SHALL NOT 丢失任一次保存结果，写入期间的读取 SHALL 只观察到完整的旧状态或完整的新状态。

#### Scenario: 并发保存不丢更新
- **WHEN** 两个保存操作（如快速连续保存两个不同工具）并发提交
- **THEN** 两次修改均反映在最终持久化文件中，后提交者基于前者的结果修改

#### Scenario: 读写互斥
- **WHEN** 一次保存尚未完成时另一处读取配置
- **THEN** 读取结果为完整的旧状态或完整的新状态，不存在中间态

### Requirement: 编辑器表单校验
编辑器 SHALL 在保存前校验表单：名称与命令内容必填；多选类型至少包含一个有效选项；输入类型至少定义一个参数。校验不通过时保存动作 SHALL 被阻止或给出明确提示。

#### Scenario: 名称缺失
- **WHEN** 名称留空时尝试保存
- **THEN** 保存不可用或被阻止，并提示名称必填

#### Scenario: 多选无有效选项
- **WHEN** 多选类型未填写任何有效选项时尝试保存
- **THEN** 保存被阻止并提示至少需要一个选项

#### Scenario: 输入无参数定义
- **WHEN** 输入类型未定义任何参数时尝试保存
- **THEN** 保存被阻止并提示至少需要一个参数
