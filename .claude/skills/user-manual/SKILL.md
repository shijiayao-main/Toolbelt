# user-manual：用户手册生成与更新

本 skill 产出的手册面向**最终用户**（用这个桌面工具分析日志的人），不是面向 AI 或开发者。判断一切内容取舍的第一问：**"一个没用过这个工具的人，照着这段文字能完成操作吗？"** 不能，就重写。

---

## 产物与位置

```
docs/manual/
├── index.md                ← 手册总目录 + 快速上手
└── <功能模块>.md            ← 每个功能模块一篇（kebab-case）
```

- 手册存放于 `docs/manual/`，与 AI 知识库（`docs/` 根与 `docs/core/`、`docs/pages/`）**分开维护**
- `docs/index.md` 是 AI 知识库索引，**不要**把手册条目混进去；若想互相发现，可在手册 index 与知识库 index 各加一行指向对方的链接即可

## 功能模块划分（本项目的权威划分）

手册按功能模块组织，划分以导航结构为准。工具分组章节的真源是 `page/home/ToolPageRegistry.kt`（feature Contributions 注册）；设置与调试入口不属于工具分组（`navItem = null`），注册在同一文件，各占一篇：

| 手册章节 | 模块 | 覆盖内容 |
|---------|------|---------|

| xlog-decode.md | XLog 解析 | 加密日志解密为可读文本 |
| tag-filter.md | Tag 过滤 | 按 Tag 正则抽取日志 |
| file-splitter.md | 文件分割 | 大文件按 MB 分片 |
| shell-tools.md | Shell 工具 | 快捷指令执行、自定义命令、设备选择、历史 |
| timestamp.md | 时间戳 | 时间戳 ↔ 日期时间转换 |
| archive.md | 解压 | zip / tar / gz 解压到同级 _extracted、7z 与三类分卷组（.zip.001 / .7z.001 / .z01）、防炸上限与 zip-slip 跳过 |

## 写作规范

**视角与语气**：
- 全程用户视角：说"你要做什么"，不说"这个类做了什么"；不出现类名、文件路径、DataStore key
- 面向任务，不面向代码结构；每篇开头一句话说清"这篇教你做什么"

**结构模板**（每篇统一）：

```markdown
# 功能名

一句话：这个功能帮你做什么。

## 什么时候用
典型场景 2-3 条（用户自己的语言）。

## 怎么用
1. 进入页面：点 dock 空间图标切空间（快捷键 Ctrl+1..5）或页内子签切换；按 Ctrl+K 搜页面名直达——以 docs/manual/index.md「怎么找功能」的现役导航心智为准，写作时先读该页
2. 操作步骤，配界面元素名（按钮/输入框/开关的实际文案）
3. 结果在哪里（输出文件位置 / 界面反馈 / 状态提示）
```

**必备栏目**（视功能酌情，缺的删掉）：
- **注意**：会丢数据/覆盖文件/失败的情形（如"输出文件已存在时不会覆盖"）
- **常见问题**：2-4 条，从知识库 FAQ 与错误提示反推用户的真实困惑（如"提示 adb 找不到→去设置页检查 ADB 路径与 Shell 类型"）
- **小技巧**：快捷导入、批量操作、一键打开输出目录等

**格式**：
- 中文，短句、步骤化、列表优先
- 界面元素用「引号」标注实际按钮文案
- 每篇 ≤150 行；超了说明拆分粒度不对，回头切模块
- 不贴代码、不贴 JSON 配置原文（shell_tools.json 的编辑说明除外，用户需要它能看懂字段含义——此时用简表转述，不贴完整 JSON）

## 执行流程

### 生成/更新一篇手册的标准流程

1. **定位素材**（按优先级）：
   - AI 知识库对应篇（`docs/pages/<功能>.md`）——行为细节的权威来源
   - 翻译不了的知识库欠账区域（无专篇的页面：XLog/Tag 过滤/文件分割/时间戳页）——读对应页面源码 + ViewModel 提取用户可见行为
   - `page/**` 下的实际界面文案（按钮/提示语）——手册里「按钮名」必须与真实 UI 文案一致，以源码字符串为准
2. **核对功能边界**：输入限制（位数/格式/文件类型）、失败行为（覆盖策略/报错文案）、持久化行为（哪些设置跨重启保留），全部以源码为准
3. **写/更新该篇**：套上面的结构模板；更新过的功能重点核对「怎么用」步骤与「注意」
4. **维护 `docs/manual/index.md`**：目录 + 一句功能简介 + 快速上手（首次使用推荐路径：设置 ADB 路径 → Shell 工具/日志分析…）
5. **自检**：
   - 每篇开头一句话能否独立回答"这是什么"
   - 步骤里的入口、按钮名与源码 UI 文案一致
   - 无类名/路径/DataStore key 泄漏到用户手册
   - ≤150 行
   - 向用户汇报：新增/更新了哪些篇、素材来自哪里、哪些行为是读源码确认的

### 全量生成手册

首次生成全量手册时：

1. 建 `docs/manual/`，先写 `index.md`（总目录 + 快速上手）
2. 按上表逐篇生成，每篇走标准流程
3. 完成后汇报覆盖矩阵：功能模块 × 手册篇目，标出哪些篇基于知识库、哪些基于源码直读
